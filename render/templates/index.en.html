A risk-adaptive assurance protocol for software changes. Every architectural commitment is written before the code lands, and the kernel checks it on every merge.

Install mathc How it works

Quick start — 60 seconds

  1. curl -sSfL https://math-coding.sh/install.sh | sh
    Installs the mathc binary and drops a user-skill into ~/.config/opencode/skills/.
  2. mathc new-decision my-first-change
    Creates decisions/my-first-change.yaml with the template, validates it, and tells you what is missing.
  3. mathc self-check
    Reads the decision store, walks every obligation, and prints one verdict per row: pass, fail, unknown, stale or missing. CI exits non-zero on any non-pass.

Moderation in one screen

math-coding gives a reviewer exactly one screen: the claim the author made, the evidence that backs it, and a single verdict. No more scrolling through a 30-file PR to see whether the change actually does what the commit message says.

The gate subcommand evaluates the change against the active policy. The self-check subcommand is the machine-readable version, designed to run in CI on every push and every merge.

The methodology

Four primitives, each one a plain file you can grep, review and revert:

Intent

Every change begins with one sentence in plain language: what should become true?

Decision

The intent becomes a YAML packet in decisions/ that names the obligations it creates, the risks it accepts, and the counter-example that would falsify it.

Obligation

A claim that can be checked by code: a fixture, a property, a benchmark, a static rule. Each one has a verdict.

Attestation

Evidence that the obligation was met on a specific commit. Tests, reviewers, audits — all stored as first-class artefacts, never as screenshots.

The working chain in full: intent → decision → obligation → change → attestation → revision. Read the methodology for the formal algebra, or foundations for the philosophical anchors.

Adopt math-coding in your repo

The protocol is small: every change writes a decisions/<id>.yaml packet before the code lands. Read the adoption runbook for a 10-minute walk-through, or clone the repo and run mathc self-check against a sample decision to see the verdicts on your machine.
