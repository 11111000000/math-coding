# Каталог обязательных отказов

Это отрицательный safety case реализации, а не самостоятельное определение
метода. Положительная модель находится в
[методологии](../skills/math-coding/references/METHODOLOGY.md). Каждый сценарий
имеет accepting и rejecting fixture. Историческая реализация может
использоваться только как отрицательный образец, не как активная версия.

1. Проверка без control не даёт `Holds` и приводит к `Inconclusive`.
2. Control изменил elsewhere/nothing — `Holds` запрещён.
3. Проверка упала по несвязанной причине — нет установленного утверждения.
4. Хотя бы один путь scope вне цели — отказ.
5. Просроченное ревью видно в map и route.
6. Изменение claim definition инвалидирует evidence.
7. Изменение verifier инвалидирует зависимые evidence.
8. Изменение environment не допускает сравнение evidence.
9. Истёкший waiver возвращает gap, `Refuted` не покрывается.
10. Постоянная спецификация и отсутствие новой записи не повышают доверие к
    произвольному факту о коде.
11. Untracked файл входит в repository surface.
12. Dirty working tree совпадает с digest того же содержимого, а не HEAD.
13. Symlink, Unicode, spaces и удалённые пути обрабатываются без потерь.
14. Несуществующий scope не даёт digest.
15. Команда 127 — `not-run`, не fail и не pass.
16. Timeout/signal/setup failure — `infrastructure-error`.
17. Пустой scope — не wildcard freshness.
18. Неизвестное/duplicate nested JSON field отклоняется.
19. Изменение теста вместе с реализацией — отдельный protected transition.
20. Политика не может авторизовать саму себя.
21. Evidence иной версии или с неполными обязательными привязками отклоняются.
22. ADR не меняется при import/adopt.
23. Изменение ADR даёт `source_changed`, но не переписывает историю.
24. `acceptance.any` не превращается молча в `all` или пропадает.
25. Нет placeholder scope и автоматической активации import.
26. `map`, `next`, `context` не изменяют файловую систему.
27. Control не меняет живое дерево даже при сбое.
28. MCP stdout содержит только JSON-RPC; ошибка домена — `isError=true`.
29. `structuredContent` соответствует `outputSchema`.
30. Установленный `stand` находит установленный `mathc` без MATHC.
31. Portable не ссылается на Nix interpreter/RPATH.
32. `doctor` сообщает об устаревшей/отсутствующей странице без изменения её.
33. Удалённые файлы не появляются в repository surface и isolated snapshot;
    новые файлы входят в индекс копии для Git/Nix-проверок.
34. Установленный `.#stand` содержит `mathc` рядом и проходит внешний smoke.
35. Повреждённый evidence trail и неизвестный `record --outcome` отклоняются
    без исключения или подмены класса результата.
36. Timeout, сигнал и необычный код выхода — `infrastructure-error`, не `not-run`.
37. `review-source` отклоняет чужое имя и пустую причину, сохраняет прежний
    digest и не даёт green без нового run; неизменённый источник отклоняется.
38. Установщик идемпотентен, отклоняет перезапись чужого файла без `--force`,
    сохраняет backup при обновлении и проверяет запуск установленного бинаря.
39. Portable smoke устанавливает бинари и skill в отдельные каталоги и использует
    установленные `mathc`/`mathc-stand`, а не путь в исходном дереве.
40. При одинаковом timestamp выбирается последняя запись evidence в trail, а
    не прежний исход; каждый тест, вызывающий mathc, объявляет зависимость Dune.
41. `mathc help COMMAND` описывает аргументы и допустимые значения; неизвестная
    команда завершается кодом 2.
42. `mathc-stand --help` описывает колонки, единицы и все стоимостные флаги.
43. `uncovered` ограничен scope цели и исключает служебные файлы метода;
    независимый agent onboarding проходит без чтения реализации.
44. Изолированная копия сохраняет режим файла, а digest предмета включает
    права; chmod инвалидирует evidence, а control не падает из-за потерянного
    executable-бита.
45. Разные непустые environment fingerprints дают `outdated`, а не `holds`.
46. `judgment` без внешнего review не устанавливается; machine-only judgment не
    становится `holds`.
47. Absolute/traversal scope/source paths и symlink отклоняются; setup и Git
    errors возвращают инфраструктурную ошибку, а не пустое состояние.
48. `mathc-stand` отклоняет отрицательные/нечисловые cost parameters и unknown
    options.
49. Установленный кандидат проверяется до замены рабочего бинаря; failed upgrade
    сохраняет прежний бинарь.
50. `Any` коротко замыкается после первого pass, а output truncation не
    превращается в успешный verifier.
51. `All` после `inconclusive`, `infrastructure-error` или `not-run` выполняет
    остальные ветви, поэтому поздний `fail` даёт `Refuted`; после `fail`
    оставшиеся команды не выполняются.
52. Установленный skill содержит полную методологию; её отсутствие или потеря
    при обновлении обнаруживается installer и portable smoke проверками.
