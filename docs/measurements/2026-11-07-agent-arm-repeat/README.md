## Задача — из собственной диагностики проекта

## Посаженная поломка

```ts
// src/components/CartProvider.tsx
- const count = lines.reduce((sum, l) => sum + l.qty, 0);
+ const count = lines.reduce((sum, l) => sum + 1, 0);
```

Счётчик корзины показывает число позиций, а не число изделий. **Проверки
проекта её не видят**: `npm run typecheck` на копии с поломкой — exit 0.
Это и делает «поймал» значащим: поймать может только агент, а не проверка.

тридцати пяти чтений исходников в первом замере.

## Почему рука A починила, а рука B — нет

Не потому, что метод «ловит дефекты». Разбор такой:

- **Обе руки поломку заметили.** B прямо написала про неё в отчёте.
- **Рука B решила, что это не её правка** — незакоммиченный чужой diff.
- **Рука A объявила утверждение о счётчике** (`cart-count-is-units`) — потому
  что карта метода показала, что `src/components/CartProvider.tsx` не
  покрыт ни одним утверждением. Объявив, она взяла это на себя и
  починила.

Механизм, который виден здесь, — не «метод ловит дефекты», а **объявление
делает вещь своей**: пока предмет не объявлен, он чужой.

## И одновременно — метод поломку НЕ поймал

Это важно и неудобно, поэтому написано прямо. След руки A:

```text
cart-count-is-units    verifier  verified
```

Утверждение «счётчик показывает число изделий» было **проверено и признано
верным**, хотя код делал `sum + 1`. Проверял его `typecheck`, а typecheck
логическую ошибку не видит. То есть:

- метод не поймал поломку;
- поймал её агент, читая код, пока делал задачу;
- и метод записал ложное утверждение как проверенное.

Это ровно то, что записано в принципе П1: «проверка обязана быть непустой и
привязанной к существующему предмету, но **её содержание** метод не
проверяет». Здесь это видно в следе, а не в формулировке.

## Вердикт критерия GOAL.md

Стенд на протокольной копии:

```text
project                            claims uncovered  caught  stale  protocol price-arm overhead
/tmp/g2-arm-a                           4        10       0      2      15.2      14.2      1.0
```

Числитель критерия — дефекты, пойманные **методом**, то есть опровергнутые
утверждения. Их ноль: ни одно утверждение не было опровергнуто, потому что
дефект был починен до того, как его коснулся проверяющий. Ноль в числителе —
левая часть критерия не определится, и цена дефекта тут ничего не меняет.

Стоит сказать прямо, что это делает замер слабее, а не сильнее: поломку
поймал агент, а не механизм. Чтобы числитель метода что-то считал, нужен
закон, который проверяет содержание, — а это и есть нерешённая половина
шага L.

## Чего этот замер НЕ доказывает

1. **Страница и метод не разделены.** Рука A получила и то, и другое; что
   именно привело к починке — карта, объявление или страница — по этому
   замеру не различить.
2. **Один случай.** Одна задача, одна поломка, один проект.
3. **Предмет мал и его проверка — typecheck.** Машинная стоимость несравнима
   с замером на wavecode (2036 тестов).
4. **Реальный дефект (drawer слева) нашли обе руки** — он виден в браузере.
