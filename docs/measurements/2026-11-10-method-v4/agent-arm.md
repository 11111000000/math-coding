# Рука агента — 2026-11-10: две руки на `yeah`, и почему контрольной руки не вышло

> Это запись измерения, а не отчёт о нём. Процедура и числа — чтобы
> результат можно было повторить или оспорить. И — чтобы результат
> можно было **не принять**.

## Предмет

`yeah` — Emacs Lisp агентский каркас, взявший math-coding v4 неделю назад
(коммит `c14dbad`). Выбран потому, что это единственный местный проект,
который **живёт по методу**: его `AGENTS.md` предписывает v4, его
`spec.json` и `waves/` — его собственные, и его собственная полоса
проверок уже устроена так, как метод требует.

## Задача

Его собственная следующая волна: **wave-03 — «the scheduler: the tools of
one answer run together»**. Не придуманная: волна объявлена в
`waves/wave-03.json`, с замыслом, проверками, обещанием и сильнейшим
возражением против подхода.

## Посаженная поломка

В `lib/yeah-codes.el`, функция `yeah-codes--string-p-or-error`: нестроковое
имя приводится к строке (`(setq name (format "%s" name))`) вместо того,
чтобы поднять `user-error`, — хотя доктрина говорит, что поднимет.

**Проверки проекта её не видят**: `8/8 passed` в
`tests/unit/test-yeah-codes.el` — ни один тест не вызывает эту функцию с
нестроковым именем. Поломка одинакова в обеих копиях.

## Руки

|---|---|---|

|---|---|---|

| контекст, токенов | 265 575 | 234 803 |
| действий агента | 259 | — |

Контроль руки A укусил **по существу**, а не формально: канарейка
`check-tools-run-in-parallel.el` на сломанном предмете упала с «the calls
of one answer did not overlap» — то есть проверка не просто покраснела,
а покраснела **по той причине, по которой должна**.

## Почему сравнение недействительно

**Контрольной руки не вышло, и это не ошибка опыта — это устройство опыта.**

Рука B была лишена метода: страница вырезана, `spec.json` и `waves/`
удалены, удаление **закоммичено**, чтобы никакая команда git не могла их
вернуть. И рука B **восстановила их сама** — из истории того же
репозитория:

> I **restored `spec.json` and `waves/`** from this repository's own
> history (`c1c09f8^`): this copy had them deleted by "the method is not
> part of this copy", yet the wave's `touches` names them and
> `./scripts/dev gate` cannot run without them.

Это **второй раз** за историю метода, когда контрольная рука оказывается
не контрольной, и замер 2026-11-07 называл это прямо: «Рука B не была
без протокола. `AGENTS.md` проекта предписывает math-coding v3». Тогда
решение было — перенести замер на проект, который о методе не знал
(Glass). Стекло не сохранилось.

**Вывод, который стоит дороже самого замера: в клоне проекта, взявшего
метод, «руки без метода» не бывает.** Метод остаётся в истории коммитов
и в собственной шапке проекта, и агент, которому сказали, что проект
живёт по методу, восстановит метод по первому же затруднению — а
затруднение находится сразу, потому что проверки проекта не запускаются
без `spec.json`.

Значит, честная контрольная рука требует **предмета, который о методе не
знал**. Такого предмета в этом окружении нет. Следующий замер обязан
либо найти такой предмет, либо объявить, что сравнение идёт не «с
протоколом и без», а «с артефактами метода и без них».

## Что замер всё-таки показал

**1. Цена метода для агента — не +51% времени.** В этом замере рука с
методом и рука без метода (с оговоркой выше) стоили **20.7 и 20.8 минуты**
и **265 575 и 234 803 токена контекста**. Разница — **+13% контекста и
ноль времени**, против +51% времени и +46% контекста в замере
2026-11-07. Причина видна: страница входа стала тонкой (одно чтение),
а `mathc` научился не затирать чужую работу и не врать про контроль —
то есть агент больше не тратит время на починку инструмента.

**2. Метод на чужом проекте даёт настоящее доказательство.** Контроль
укусил, и укусил по существу. `mathc audit` на реальном проекте: **16 из
28 утверждений смотрят на свой предмет**, 12 не установлены. Это первое
число о проверках чужого кода, которое у метода вообще есть.

**3. Артефакты метода — несущая конструкция, а не украшение.** Рука, которой
метод запретили, восстановила его по первому затруднению, и сказала
почему: без `spec.json` и `waves/` не запускается собственная полоса
проверок проекта. Рычаг метода — в соглашении, а не в бинарнике.

**4. Метод поймал ложь в собственной книге.** Рука B починила утверждение,
у которого контроль **молча устарел**: он указывал на
`(yeah-tools-call name args)`, а волна эту функцию убрала, и утверждение
тихо стало `inconclusive`. Никакая проверка этого не видела — видел
`mathc`.

**5. Посаженную поломку увидели обе руки.** Карта у обеих красная по
одной и той же причине — `ptc-sandbox-restricts-model-code`, а это и есть
посаженная поломка. Рука B назвала её прямо («the defect planted in
commit `d14e875` in `lib/yeah-codes.el`»); рука A заметила, что файл
изменён, и не стала его разбирать. **Разница — один шаг рассуждения,
при n=1, и при недействительном сравнении это не результат.**

## Чего этот замер НЕ доказывает

1. **Полезности.** Критерий GOAL.md не считается: пойманных дефектов ноль.
2. **Сравнения рук.** Оно недействительно, и это сказано выше.
3. **Что метод находит дефекты.** Поломка была логической, в непроверяемой
   ветке, — а закон О2 прямо говорит, что решение о смысле не
   опровергается процедурой. Метод её не видел и не мог: он честно
   говорит, что его проверка **не показана** способной ловить этот класс
   ошибок.

## Процедура повторения

```sh
git clone <yeah> /tmp/yeah-arm-a
git clone <yeah> /tmp/yeah-arm-b
# в обеих копиях: одинаковая посаженная поломка в lib/yeah-codes.el
# в копии B: вырезать блок math-coding из AGENTS.md, удалить spec.json и
#   waves/, и ЗАКОММИТИТЬ удаление — иначе git вернёт метод
#   (в этом замере именно так и вышло)
# в копии A: mathc install — страница входа
# затем: две руки, одна и та же модель, одна и та же задача
```
