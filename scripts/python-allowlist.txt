# scripts/python-allowlist.txt — the Python files this repository admits.
#
# WHAT THIS IS. The kernel is OCaml — lib/ and bin/ are OCaml, and no
# kernel call path requires a Python interpreter. That rule is stated
# in decisions/mathc-counters-subcommand-2026-10.yaml, which
# replaced the last Python helper in a kernel call path with the
# `mathc counters` subcommand.
#
# The TOOLING around the kernel is a different question, and this file
# is the answer to it: these are the Python files the repository
# admits, one path per line. A Python file that is not on this list is
# not a decision to write Python — it is a decision that was not
# written down, and `tests/fixtures/no-new-python-in-the-tree.sh`
# fails on it.
#
# HOW TO ADD ONE. Add the path here, in the same commit that adds the
# file, and say in that commit WHY the kernel could not do it. The
# edit is the record: a reader of the diff sees the new Python and
# the reason next to it. That is the whole mechanism - the house's
# answer to "the corpus cannot grow back", applied to a language.
#
# WHAT BELONGS HERE. A tool that is not part of the kernel and not
# part of the protocol: a generator, a linter, an importer, a release
# manifest renderer. What does not belong: anything the kernel calls,
# anything an adopter's tree needs, and anything whose absence would
# change what the kernel does.
#
# MEASURED 2026-11-01: ten files, 2130 lines. The eleventh
# (tools/attest-helper.py) was deleted on that date - it was the older
# twin of scripts/generate-attestations.py, it named itself as such in
# its own docstring, and nothing in the repository referred to it.
#
# FORMAT
# ------
# One repository-relative path per line. A line whose first non-blank
# character is `#` is a comment; a blank line is ignored. Every other
# line is a path that must exist. A path on this list that does not
# exist is itself a failure: the list may not carry a stale entry.
