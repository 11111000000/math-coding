## Why

65 строк ручного скана — самый длинный фрагмент императивного кода в проекте. Содержит три категории проблем: (1) мёртвый код (шаг 5 после шага 4 не может сработать из-за lowercase), (2) регрессия против Markdown (якоря лоуэркейсятся), (3) нет тестов — функция string→string с императивной логикой внутри, проверить поведение невозможно без рендера всего сайта. Это риск: любая правка pandoc-вывода может тихо сломать ссылки.

## Antithesis

Pandoc уже используется для рендера Markdown в HTML. Можно отдать весь markdown pandoc-у и не пытаться парсить ссылки вручную. Но это потребовало бы переписать всю render.ml (400+ строк) и сделать её зависимой от стабильности pandoc-вывода между версиями. Точечный fix дешевле.

## Synthesis

Переписать шаг 2 на Str.regexp: один проход 'href="..."/' → извлечь путь до '#', лоуэркейсить только путь, якорь склеить обратно. Удалить мёртвый шаг 5. Добавить 4 теста: обычный href, href с #fragment, href без значения, href с query string. Точечная правка ~20 строк вместо 65, тестируемо.
