## Why

Skip и Fail — разные вещи в логике V-предикатов: Fail = 'конвенция нарушена, нужно исправить', Skip = 'этот пакет пропущен по конфигурации'. Сливать их в один счётчик означает, что mathc check --json будет сообщать '9 fail' когда 5 из них Skip. Для CI, который интерпретирует exit code и парсит JSON, это регрессия против обещания '4 категории verdicts — Pass, Warn, Fail, Skip'.

## Antithesis

Skip никто не возвращает сейчас (kernel S не имеет логики Skip). Фикс меняет поведение для кода, которого ещё нет. С другой стороны, summarize предназначен быть функцией общего назначения — если сейчас ничего не возвращает Skip, это случайность, а не инвариант. Возможный контр-аргумент: Skip и Fail визуально похожи (оба требуют внимания), и старая агрегация удобна для дашбордов.

## Synthesis

Skip → (p, w, f, s + 1) — Skip учитывается отдельно. Добавить тест в test_check: создать список с Skip-вердиктом, проверить, что p/w/f не изменились, а s увеличился. Стоимость: 2 строки правки, один тест. Выгода: инвариант 'Skip != Fail' сохраняется в коде, даже пока никто не выдаёт Skip.
