# FAQ

> **Frequently asked questions.** The protocol is small;
> the questions are not.

### What is math-coding?

A discipline of recording architectural commitments as
packets before the code that implements them. The kernel
(`mc`) checks the commitment against the code on every
merge.

### What is mathcoding?

The methodology that the kernel implements. Math-coding
is the kernel; mathcoding is the discipline.

### Why eight principles, not one?

The eight are the **minimum set** that closes the
bootstrap loop. From the first commit (`v3-alpha-0.0.1`)
to the moment the kernel can check itself (commit
`8fa7fcf`), every change had to be admitted by all
eight. Drop any one, and the loop stays open.

### Why not pull in a real YAML library?

The kernel must remain offline and side-effect-free
(`OCAML_BEST_PRACTICES.md` §1.3, §7.3). Adding a parser
dependency would break the reproducibility guarantee the
kernel is built around. The hand-rolled subset loader is
sufficient for the bootstrap files and stays tiny.

### Why a hand-rolled Markdown subset for `mc render`?

Same reason. The published prose uses a narrow subset
(headings, paragraphs, lists, code blocks, sidenotes).
A 200-line parser is auditable. A full Markdown library
adds transitive packages and breaks the closure.

### Why Tufte style?

Three reasons. (1) Margins — the protocol is dense; the
reader needs room for sidenotes and references. (2)
Serif — Charter / Iowan Old Style reads slower and
retains attention better at long-form prose than
sans-serif. (3) Restraint — Tufte's palette uses a
single accent; the protocol's communication model is the
same: one important thing per paragraph.

### Why bilingual English + Russian?

The author is Russian; the protocol's primary audience
is the English-speaking developer community; the Russian
audience is large enough that shipping without a
translation is a real cost. Both audiences read the
kernel output.

### Why MathJax, not KaTeX?

MathJax 3 is the conservative choice; it supports the
full TeX/LaTeX grammar and survives malformed input
gracefully. KaTeX is faster but a narrower subset. The
protocol's prose does not need the speed.

### Why GitHub Pages?

Static + free + the deployment already exists
(`.github/workflows/site.yml` pinned to `ubuntu-22.04`).
The site is a self-consumer: it is generated by the same
kernel that it describes.

### Can I host my own deployment?

Yes. The dist/ tree is portable; serve it with any static
host (nginx, Caddy, GitHub Pages, Netlify, Vercel,
Cloudflare Pages). Override the `<base href>` with
`--site-base ""` (root-relative) or `--site-base /my-app/`
to match the deployment path.

### What if I disagree with an axiom?

Open an issue. The axioms are derived from the
self-application principle: a system whose rules do not
govern themselves cannot be trusted. To revise an axiom
is a **protected policy transition** and requires a
decision under the prior policy, the strongest
countercase, positive + negative fixtures, a migration
path, recovery path, prior authorization, and a verdict
diff. See `AGENTS.md` §Self-application.
