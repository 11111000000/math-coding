# Аксиомы

> Пять нормативных аксиом math-coding. Каждая аксиома — это
> ограничение на то, что ядро вправе утверждать, а не функция,
> которую ядро поставляет. Полные формулировки находятся в
> `axioms/`; эта страница — их прозаическое резюме.

## A0 — Разделение

<figure class="mathc-axiom-figure">
<img src="assets/axiom-separation.svg" alt="Аксиома A0 — Разделение: виды различны, цепочка идёт в одну сторону.">
</figure>

Виды различны; цепочка идёт в одну сторону.

Существуют объекты следующих видов:

```text
intent, decision, obligation, change, attestation, observation, revision
```

Никакие два из них не являются одним и тем же объектом.
Намерение — это не решение. Решение — это не обязательство.
Изменение — это не аттестация. Цепочка идёт только в одну
сторону. Ревизия не возвращается к решению; она либо
заменяет его, либо нет, и это решается явным полем
`Decision.supersedes`.

## A1 — Обратная связь

<figure class="mathc-axiom-figure">
<img src="assets/axiom-feedback.svg" alt="Аксиома A1 — Обратная связь: у каждого обязательства есть путь к наблюдению.">
</figure>

У каждого обязательства есть путь к наблюдению.

Для каждого обязательства в системе существует путь, по
которому мир сообщает системе, выполняется ли оно. Этот путь:
`обязательство -> предсказание -> наблюдение -> ревизия`.
Без наблюдения обязательство — лишь пожелание.

## A2 — Инварианты и восстановление

<figure class="mathc-axiom-figure">
<img src="assets/axiom-invariants.svg" alt="Аксиома A2 — Инварианты и восстановление: каждый инвариант спарен с путём восстановления.">
</figure>

Каждый инвариант спарен с путём восстановления.

Для каждого инварианта `I` существует оператор восстановления
`R`, такой что если `I` не выполняется, система обнаруживает
дефицит с авторизованным средством исправления. Средство
исправления авторизовано, когда существующий ответственный
может его выполнить. Блокирующее решение, не называющее
средства исправления, само по себе является дефицитом.

## A3 — Само-применимость

<figure class="mathc-axiom-figure">
<img src="assets/axiom-self-application.svg" alt="Аксиома A3 — Само-применимость: правила управляют собственными изменениями.">
</figure>

Правила управляют собственными изменениями.

Для каждого перехода `(K_n, P_n) -> (K_{n+1}, P_{n+1})`
переход удовлетворяет:

```text
Gate_{K_n, P_n}(transition) = Open
Conformance(K_{n+1}) = Pass
Migration(K_n, K_{n+1}) = Pass
VerdictDiff(K_n, K_{n+1}) subset DeclaredSemanticChanges
SelfVerify(K_{n+1}, P_{n+1}) = Pass
```

В частности: `P_{n+1}` НЕ ДОЛЖНО участвовать в авторизации
собственного принятия. Кандидатная политика не может
авторизовать собственное принятие.

## A4 — Забота

<figure class="mathc-axiom-figure">
<img src="assets/axiom-care.svg" alt="Аксиома A4 — Забота: ответственный, последствие, подотчётность, срок пересмотра.">
</figure>

Ответственный, последствие, подотчётность, срок пересмотра.

Для каждого обязательства, решения, аттестации или waiver
система называет:

```text
кто выигрывает, если оно выполняется
кто проигрывает, если оно нарушается
кто за него подотчётен
когда оно будет пересмотрено
```

Эти четыре пункта не подлежат обсуждению. Это минимальное
содержание *заботы о результате*.

## Как ядро их обеспечивает

| Аксиома | Механизм ядра |
|---------|---------------|
| A0 | Запечатанные варианты для тегов видов в `lib/domain.ml`; префиксы дайджестов по видам; закрытый `additionalProperties` в JSON-схемах |
| A1 | Перечисление `result` включает `Inconclusive` и `InfrastructureError` отдельно от `Pass`; waivers содержат `expires_at`; операционные исходы допускают `absence_means: inconclusive` |
| A2 | Вариант шлюза включает `Blocked` с `remedies`; диагностика содержит `next_actions`; коды выхода `0/1/2/3` согласно `OCAML_BEST_PRACTICES.md §4.3` |
| A3 | Активная политика в `decisions/decision.yaml` ссылается на этот указатель; изменения конституции требуют миграции и соответствия; старая политика авторизует новую |
| A4 | `decision.risk.owner`, `obligation.decision`, `assumption.owner`, `waiver.issuer`, `attestation.producer_identity` обязательны, а не опциональны |

Полный цикл обеспечения на v3.0.0.20 описан на странице
[methodology](methodology.html).
