# FAQ

> **Частые вопросы.** Протокол мал; вопросы — нет.

### Что такое math-coding?

Дисциплина записи архитектурных обязательств как
пакетов раньше кода, который их реализует. Ядро (`mc`)
проверяет обязательство на соответствие коду при
каждом merge.

### Что такое mathoding?

Методология, которую реализует ядро. Math-coding — это
ядро; mathoding — это дисциплина.

### Почему восемь принципов, а не один?

Восемь — это **минимальный набор**, закрывающий петлю
bootstrap. От первого коммита (`v3-alpha-0.0.1`) до
момента, когда ядро может проверить себя (коммит
`8fa7fcf`), каждое изменение должно было быть одобрено
всеми восемью. Уберите любое — петля остаётся открытой.

### Почему не подключить настоящую YAML-библиотеку?

Ядро должно оставаться офлайн и без побочных эффектов
(`OCAML_BEST_PRACTICES.md` §1.3, §7.3). Добавление
зависимости парсера втащило бы транзитивные пакеты и
сломало гарантию воспроизводимости, на которой построено
ядро. Самописный загрузчик подмножества достаточен для
bootstrap-файлов и остаётся крошечным.

### Почему самописное подмножество Markdown для `mc render`?

По той же причине. Опубликованная проза использует
узкое подмножество (заголовки, параграфы, списки,
блоки кода, сноски). Парсер на 200 строк аудитабелен.
Полная Markdown-библиотека добавляет транзитивные
пакеты и ломает closure.

### Почему стиль Tufte?

Три причины. (1) Поля — протокол плотный; читателю нужно
место для сносок и ссылок. (2) Serif — Charter / Iowan Old
Style читается медленнее и удерживает внимание лучше на
длинной прозе, чем sans-serif. (3) Сдержанность — палитра
Tufte использует один акцент; коммуникационная модель
протокола та же: одна важная вещь на абзац.

### Почему билингва English + Russian?

Автор — русский; основная аудитория протокола —
англоязычное сообщество разработчиков; русская
аудитория достаточно велика, чтобы поставка без
перевода была реальной ценой. Обе аудитории читают
вывод ядра.

### Почему MathJax, а не KaTeX?

MathJax 3 — консервативный выбор; поддерживает полный
грамматик TeX/LaTeX и терпит неправильный ввод. KaTeX
быстрее, но это более узкое подмножество. Прозе
протокола скорость не нужна.

### Почему GitHub Pages?

Статика + бесплатно + деплой уже существует
(`.github/workflows/site.yml` пиннут на `ubuntu-22.04`).
Сайт — самопотребитель: его генерирует то же ядро,
которое он описывает.

### Могу ли я поднять собственный деплой?

Да. dist/-дерево портативно; подавайте его любым
статическим хостом (nginx, Caddy, GitHub Pages,
Netlify, Vercel, Cloudflare Pages). Переопределите
`<base href>` через `--site-base ""` (root-relative) или
`--site-base /my-app/`, чтобы соответствовать пути
деплоя.

### Что если я не согласен с аксиомой?

Откройте issue. Аксиомы выводятся из принципа
само-применения: система, чьи правила не управляют
собой, не может вызывать доверия. Пересмотр аксиомы —
это **защищённый плаги-переход** и требует решения под
предыдущей политикой, сильнейшего контраргумента,
позитивных + негативных фикстур, пути миграции, пути
восстановления, авторизации от предыдущей политики и
verdict diff. См. `AGENTS.md` §Self-application.
