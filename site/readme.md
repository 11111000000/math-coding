# math-coding

> **A discipline of recording decisions before code.**
> The kernel is a single static binary; packets are plain
> text and live in `decisions/`; verdicts are produced by
> `mc gate` and `mc self-check`.

## What it is

math-coding links a concrete change to the obligations it
may affect and to bounded evidence about those
obligations. It does not prove software correctness.
The working chain:

```text
intent -> decision -> obligation -> change -> attestation -> revision
```

Every architectural commitment is written **before**
the code, and the kernel checks the commitment against
the code on every merge. The discipline is called
**mathoding** — math-coding applied as a methodology.

## What it ships

- A kernel (`mc`), one OCaml binary, ~700 lines plus
  transitive modules.
- Eight principles, each documented as a packet in
  `decisions/` and verifiable by a cram fixture in
  `tests/cli/`.
- A static site (`docs/`), generated by `mc render`,
  deployed to GitHub Pages.

## Five axioms + three extensions

| Group | Principle | What it asserts |
|-------|-----------|-----------------|
| foundation | `bootstrap-v3` | the kernel can check this repository |
| foundation | `kernel-conformance-runner` | every fixture is enumerated and run |
| foundation | `validate-and-context` | every decision parses and exposes a capsule |
| foundation | `gate-decision` | the gate verdict is machine-checked |
| foundation | `attestation-store-fill` | the attestation store is populated |
| extension | `mc-explain-subcommand` | `mc explain` resolves a `decision:` ref |
| extension | `mc-self-check-subcommand` | `mc self-check` returns an automated verdict |
| extension | `mc-packages-subcommand` | `mc packages` is a first-class surface |

See [Foundations](foundations.html) for the full mapping
from each axiom to its kernel mechanism and verification
obligation.

## Quick start

```sh
nix develop .#test
dune build
dune test
mc self-check     # prints a JSON verdict; exit 0 = pass
```

To render the site locally:

```sh
scripts/render.sh         # builds mathc, runs `mc render`,
                          # verifies the dist/ allowlist
python3 -m http.server -d dist/ 8000
# open http://localhost:8000/
```

## Commands

| command | purpose |
|---------|---------|
| `mc validate FILE` | parse FILE as a decision |
| `mc context BASE HEAD --budget N` | print a JSON context capsule |
| `mc explain DETAIL_REF` | resolve `decision:<id>` to a body |
| `mc assess BASE HEAD` | list changed file paths |
| `mc attest FILE` | parse a JUnit XML report |
| `mc time-estimate --class ... --count N` | forecast from a reference class |
| `mc gate BASE HEAD` | gate verdict against the attestation store |
| `mc self-check` | automated self-verification |
| `mc packages --format=text\|json\|html` | package grid |
| `mc render [--lang en\|ru\|both]` | render the static site |

## Where things live

| path | what |
|------|------|
| `lib/` | pure OCaml kernel modules |
| `bin/` | the `mc` CLI dispatcher |
| `decisions/` | decision + obligation packets (the assurance surface) |
| `attestations/` | attestations keyed by SHA (the evidence surface) |
| `axioms/` | the five axioms as Markdown |
| `spec/` | constitution + semantics + algebra (the formal layer) |
| `site/` | published prose, in EN + RU |
| `tests/cli/*.t` | cram fixtures for the CLI |
| `tests/*.ml` | kernel unit + conformance tests |
