# Манифест

> **Восемь принципов, один статический исполняемый файл.**
> Math-coding — это дисциплина записи архитектурных решений
> **до** кода; ядро проверяет соответствие записи.

## Зачем это существует

Кодовая база без записей решений расходится с замыслом.
Архитектор принял решение на третьей неделе, забыл о нём
к девятой, а к семнадцатой исходная причина утрачена —
остался только код, который без археолога не восстановить.
Типичное решение — документация; типичная неудача — то, что
документация не сверяется с кодом.

Math-coding обращает неравенство: каждое архитектурное
обязательство записывается **до** кода, а ядро сверяет
обязательство с кодом при каждом слиянии. Дисциплина
называется **mathcoding** — math-coding как методология
изменений в программах.^[Минимальный вызов, закрывающий
петлю обратной связи в дисциплине процесса, — верификатор:
программа, которую можно перезапустить, чей код выхода
означает «успех» или «провал».]

## Чем оно не является

- Не исполнителем непрерывной интеграции. Используйте
  `scripts/dev` или механизм GitHub Actions.
- Не генератором документации. Спецификация нормативна;
  инструменты читают спецификацию.
- Не инструментом обзора кода. Используйте агентов
  `paseo` или встроенное в GitHub рецензирование.
- Не наблюдателем среды исполнения. Ядро работает
  офлайн; аттестации производятся вне сборочного конвейера.

Работа ядра — **петля обеспечения качества**: каждое
обязательство имеет путь к наблюдению; каждое наблюдение
имеет известный класс источника; каждый класс источника
ограничен предметом, входами и временем.

## Восемь принципов на v3.0

Ядро проверяет восемь принципов, все оформлены как пакеты
в каталоге `decisions/`:

| Группа | Принцип | Что утверждает |
|--------|---------|-----------------|
| основа | `bootstrap-v3` | ядро способно проверить этот репозиторий |
| основа | `kernel-conformance-runner` | каждая фикстура перечислена и выполнена |
| основа | `validate-and-context` | каждое решение разбирается и открывает капсулу |
| основа | `gate-decision` | вердикт шлюза проверяется сценарно |
| основа | `attestation-store-fill` | хранилище аттестаций заполнено |
| расширение | `mathc-explain-subcommand` | `mathc explain` разрешает ссылки вида `decision:` |
| расширение | `mathc-self-check-subcommand` | `mathc self-check` возвращает автоматический вердикт |
| расширение | `mathc-packages-subcommand` | `mathc packages` — поверхность первого класса |

Восемь — не произвольное число. Это минимум, закрывающий
петлю начальной загрузки: от первого коммита
(`v3-alpha-0.0.1`) до момента, когда ядро способно проверить
само себя (коммит `8fa7fcf`), каждое изменение должно было
получить одобрение всех восьми. Сейчас оба условия
автоматические.

## Как читать этот сайт

Начните с [Methodology](methodology.html). Затем
[Axioms](axioms.html) для философских оснований. Затем
[Foundations](foundations.html) для отображения в OCaml.
Затем [Packages](packages.html) для живой поверхности
обеспечения качества.

Сайт сгенерирован самим ядром (`mathc render`). Сетка пакетов
ниже — живой вывод `mathc packages`. Страницы, которые вы
читаете, — это аргументы, которые ядро принимает о себе.
