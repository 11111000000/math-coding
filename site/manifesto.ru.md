# Манифест

> **Восемь принципов, один статический бинарь.** Math-coding — это
> дисциплина записывать решения раньше кода; ядро проверяет запись.

## Зачем это существует

Кодовая база без записей решений дрейфует. Архитектор принял
выбор на третьей неделе, забыл о нём к девятой, а к семнадцатой
исходная причина утрачена — остался только код, который нельзя
восстановить без археолога. Типичное решение — документация;
типичная неудача — документация не сверяется с кодом.

Math-coding переворачивает асимметрию: каждое архитектурное
обязательство записывается **раньше** кода, а ядро сверяет
обязательство с кодом при каждом merge. Дисциплина называется
**mathoding** — math-coding как методология для изменения
программ.^[Минимальный вызов, который закрывает петлю обратной
связи в дисциплине процесса, — верификатор: программа, которую
можно перезапустить и чей код выхода означает pass или fail.]

## Чем оно не является

- Не CI-раннером. Используйте `scripts/dev` или GitHub Actions.
- Не генератором документации. Спецификация нормативна; инструменты
  читают спецификацию.
- Не инструментом код-ревью. Используйте агентов `paseo` или
  ревью в GitHub.
- Не монитором рантайма. Ядро работает офлайн; аттестации
  производятся вне сборочного конвейера.

Работа ядра — **петля assurance**: каждое обязательство имеет
путь к наблюдению; каждое наблюдение имеет известный класс
источника; каждый класс источника ограничен предметом, входами
и временем.

## Восемь принципов на v3.0

Ядро проверяет восемь принципов, все — как пакеты в `decisions/`:

| Группа | Принцип | Что утверждает |
|--------|----------|----------------|
| основа | `bootstrap-v3` | ядро может проверить этот репозиторий |
| основа | `kernel-conformance-runner` | каждая фикстура перечислена и запущена |
| основа | `validate-and-context` | каждое решение парсится и открывает капсулу |
| основа | `gate-decision` | вердикт ворот проверен сценарно |
| основа | `attestation-store-fill` | хранилище аттестаций заполнено |
| расширение | `mc-explain-subcommand` | `mc explain` разрешает `decision:` ссылки |
| расширение | `mc-self-check-subcommand` | `mc self-check` возвращает автоматический вердикт |
| расширение | `mc-packages-subcommand` | `mc packages` — поверхность первого класса |

Восемь — не произвольное число. Это минимум, закрывающий
петлю bootstrap: от первого коммита (`v3-alpha-0.0.1`) до
момента, когда ядро может проверить себя (коммит `8fa7fcf`),
каждое изменение должно было быть одобрено всеми восемью. Теперь
оба условия автоматические.

## Как читать этот сайт

Начните с [Methodology](methodology.html). Затем [Axioms](axioms.html)
для философских оснований. Затем [Foundations](foundations.html)
для отображения в OCaml. Затем [Packages](packages.html) для
живой поверхности assurance.

Сайт сам сгенерирован ядром (`mc render`). Сетка пакетов ниже —
живой вывод `mc packages`. Страницы, которые вы читаете, — это
аргументы, которые ядро принимает о себе.
