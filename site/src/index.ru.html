math-coding

v5 · одна активная модель · ядро на OCaml

Слой проверки связей между требованиями, решениями, кодом и доказательствами. Отвечает на четыре вопроса: что должно быть истинным, чем это подтверждено и насколько независимо, что изменилось и требует перепроверки, и что остаётся неизвестным.

рабочий цикл методология

Цепочка, которую проверяет ядро

Каждое обязательство называет область, опровергатель, условия подтверждения и контроль; источник связывается при наличии. Доказательство записывается с digest'ами предмета, определения, проверки и среды — поэтому карта ниже вычисляется, а не декларируется.

Быстрый старт

Устанавливаются статические mathc и mathc-stand. Nix нужен для сборки; для запуска нужны Git, POSIX shell и объявленные проектом verifier-команды.

  1. git clone https://github.com/11111000000/math-coding && cd math-coding && ./install.sh
    Устанавливает бинари, user-scope skill и полную методологию. Чужой файл не перезаписывается; --force сохраняет резервные копии.
  2. mathc init && mathc goal "ЦЕЛЬ" "src/,test/" "ВЛАДЕЛЕЦ"
    Цель и владельца задаёт человек. Инструмент не выдумывает ни того, ни другого.
  3. mathc add ID "ТРЕБОВАНИЕ" SCOPE "ОПРОВЕРЖИТЕЛЬ" fact --requirement "verifier:КОМАНДА" --control "ЛОМАЕТ_ПРЕДМЕТ"
    Утверждение получает предмет, проверку и контроль её чувствительности.
  4. mathc run выполняет verifier на кандидате и control в изолированной копии. Затем mathc map вычисляет состояния, а mathc next называет следующее действие.
$ mathc map verdict: green core-laws holds strict-codecs holds cli-evidence holds … uncovered: 0 file(s)

Живая карта

Эта сетка не написана вручную. Она генерируется при сборке из spec.json и mathc map --json — того самого вывода, который использует CI. Если доказательство устареет, страница скажет об этом после следующей сборки.

Что v5 отказывается делать

  • Unknown никогда не показывается как успех; waiver не является pass.
  • Машинное доказательство никогда не устанавливает judgment — только внешнее человеческое ревью.
  • Изменённый ADR переводит обязательства в outdated и никогда — молча в green; история не переписывается.
  • Читающие глаголы (map, next, context) не трогают рабочее дерево; контроли исполняются в изолированных копиях.
  • Агент не может подтвердить собственную правоту одной декларацией.

Каждое обязательство на этой странице проверяется инструментом, который страница описывает. Методология — это артефакт; артефакт следует методологии.
