Рабочий цикл

Формат спецификации и формат доказательств — версия 6; инструмент — mathc 5: версия продукта не изменилась. Основной цикл: init, goal, add, run и map; next называет одно конкретное следующее действие. Читающие глаголы не изменяют рабочее дерево; контроли исполняются в изолированных копиях; человеческие решения записываются явно с автором и положенными каждому решению данными. mathc help COMMAND описывает каждый глагол и работает до создания спецификации. Полная модель находится в канонической методологии.

Основной цикл

Пример цикла в проекте, где обязательство подтверждено:

$ mathc init $ mathc goal "платежи остаются идемпотентными" "src/,test/" "anna" $ mathc add retry-safety "повторное списание не применяется дважды" \ src/payments.ml,test/payments.ml \ "двойное списание проходит набор тестов" fact \ --requirement "verifier:dune runtest test/payments.exe" \ --control "sed -i 's/dedupe//g' src/payments.ml" $ mathc run $ mathc map verdict: green retry-safety holds $ mathc next next: nothing to do - declared evidence is current and the tree is covered
глаголчто делаеттрогает дерево?
init / goalсоздают спецификацию; записывают цель и владельца, заданных человекомпишет spec.json
addобъявляет обязательство: требование, scope, опровержитель, регистр, проверка, контрольпишет spec.json

Что может прогон формата 6

Прогон формата 5 исполнил все объявленные проверки и записал доказательства. Прогон формата 6 делает больше и говорит больше.

чтокак
частичный прогонmathc run --changed исполняет только те утверждения, чьё доказательство перестало держаться, и оставляет остальные как есть
ценакаждый прогон пишет свою цену в журнал прогонов: машинные секунды по утверждениям, самые дорогие первыми (.math/v6/runs.jsonl)
пределmathc run --limit SECONDS ограничивает прогон; по умолчанию 3600 секунд
остановленный прогонон говорит, что остановлен, отдаёт карту по уже наблюдённому и выходит с кодом 4

Контроль должен быть причиной

Контроль доказывает, что проверка способна отклонить одно конкретное нарушение, и для этого проверка обязана пройти в копии до того, как контроль применён. Протокол: та же проверка сначала должна дать pass на неизменённой копии предмета, и только затем контроль применяется, проверка повторяется и обязана вернуть обычный fail. Копия, которая не может выполнить проверку сама по себе — нет зависимостей, нет toolchain, — своим отказом ничего не доказывает: наблюдение становится inconclusive с причиной copy-failed, и машинное holds недостижимо.

Проверка, которой нужны зависимости проекта, объявляет среду, в которой она выполняется: префикс среды (--environment ENV в add) готовит среду перед проверкой. Без этого объявления копия не может выполнить проверку, и причина copy-failed говорит об этом вместо ложного доказательства.

Среда и сборка инструмента

В формате 5 в fingerprint среды входил digest бинаря, поэтому пересборка инструмента обесценивала каждое доказательство разом: в одном проекте 151 подтверждение стали устаревшими, хотя ни одно из них не стало ложным. В формате 6 среда — это операционная система и зафиксированный toolchain (lock file), а сборка инструмента пишется отдельно, рядом со средой. Смена инструмента называется tool-changed и не отзывает результат: проверка была та же и предмет был тот же.

Привязка ADR

ADR хранит мотивацию и историю; math-coding ничего в него не пишет. import-adr печатает черновик, adopt перечисляет найденные источники, и только явный add --source привязывает обязательство к документу — по digest.

Решения человека

  • mathc record ID AUTHORITY --by WHO --outcome OUTCOME — записывает внешнее ревью для объявленного требования review:AUTHORITY. Существует ровно пять исходов: pass, fail, inconclusive, infrastructure-error, not-run.
  • mathc waive ID --by WHO --reason WHY --valid-for DAYS --recovery ACTION — ограниченное принятие риска. Это не pass, и оно не покрывает отказ.
  • mathc authorize --by WHO --reason WHY — работает только при наличии policy.json; это журнал разрешения, а не аутентификация.
  • mathc approve --by WHO --reason WHY [--command CMD] — одобряет команды, которые поверхность агента может исполнять в этом проекте. Без одобрения поверхность отказывает в объявлении и в запуске команды и называет её.
  • mathc install обновляет маркированный блок в AGENTS.md; mathc doctor проверяет настройку и ничего не исправляет.

Остальные глаголы

Цикл выше — это ежедневная работа. Остальные глаголы обслуживают края проекта, и ни один из них не меняет рабочее дерево, если не говорит об этом прямо.

глаголчто делает
help COMMANDописывает один глагол; работает до создания спецификации
contextпечатает ограниченный контекст задачи в JSON — капсулу, которую получает агент
adoptнаходит каталоги ADR и источников спецификации, только на чтение
import-adr PATHчитает документ MADR или adr-tools и печатает черновик утверждения; ни источник, ни spec.json не меняются
import-junit PATHразбирает JUnit XML и печатает точные числа тестов и падений
re-evaluateперечисляет утверждения, чей источник, определение или доказательства требуют ревью
review-source ID --by OWNER --reason WHYсвязывает изменённый источник после человеческого ревью; сохраняет прежний digest, очищает waiver и всё равно требует свежего run
review-decision ID --by WHO --reason WHYпересматривает решение человека по утверждению; решение привязано к решению, а не к байтам документа, который его несёт, поэтому растущий документ не делает решение устаревшим
authorize --by WHO --reason WHYзаписывает разрешение на текущие защищённые изменения при наличии policy.json; это журнал, а не аутентификация
approve --by WHO --reason WHY [--command CMD]одобряет команды, которые может исполнять поверхность агента; одобрение привязано к самим командам, а неодобренная команда не проходит
doctorпроверяет git, спецификацию, цель, защищённую политику и страницу агента, ничего не меняя
installобновляет только блок math-coding в AGENTS.md проекта; бинари он не ставит
migrateпереводит проект формата 5 на формат 6: журналы переезжают в .math/v6/, а файлы формата 5 остаются на диске
mcpотдаёт поверхность инструментов JSON-RPC через stdio

Утверждение с регистром judgment устанавливается только внешним человеческим ревью: для него add требует review:WHO и не принимает машинные verifier'ы.

Обновление проекта с форматом 5

  1. Сначала обновить инструмент проекта — его установленный бинарь и его CI. Инструмент, который читает проект, должен понимать формат 6 раньше, чем миграция ляжет в дерево: прежняя версия не читает спецификацию версии 6, и гейт проекта падает с unsupported schema_version 6.
  2. Затем mathc migrate — журналы переезжают в .math/v6/, а старые файлы остаются на диске.
  3. Затем снова mathc run — доказательства пишутся заново.

Порядок найден полевым измерением 2026-11-22 и исправлен в плане архитектуры.

Читать карту без терминала

Карту можно читать и в браузере. Консоль показывает ту же карту, очередь человека и журнал наблюдений и никогда не вычисляет состояние сама. Интерфейсы по частям.

Коды выхода

кодзначение
0green, либо действие успешно
1red, либо отказ защищённого перехода
2ошибка вызова
3unknown или vacant — состояние не установлено
4прогон остановлен — он говорит об этом и отдаёт карту по уже наблюдённому
5инструмент не смог ответить — битая спецификация или битый репозиторий

Повреждённый след доказательств не игнорируется и не считается отсутствием доказательств. Точные коды по глаголу показывает mathc help COMMAND.

Код 3 и код 5 — не один и тот же ответ. Код 3 говорит, что состояние пока не установлено; код 5 говорит, что инструмент не смог ответить вовсе. Потребитель, который читает сломанный инструмент как невыполненный проект, будет ждать работы, которая не придёт никогда.

Минимальное достаточное трение: обычная работа не требует карточек на каждый файл. Структура добавляется только там, где измерена польза.
