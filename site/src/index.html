math-coding

v5 · one active model · OCaml kernel

A checking layer between requirements, decisions, code and evidence. It answers four questions: what must be true, what proves it and how independently, what changed and must be re-checked, and what is still unknown.

the five-command loop the methodology

The chain the kernel checks

Every claim names its scope, falsifier, evidence requirements and control; a source is linked when present. Evidence records the subject, definition, verifier and environment digests — so the map below is computed, not declared.

Quick start

The installer provides static mathc and mathc-stand binaries. Nix is needed to build; running them needs Git, a POSIX shell and the verifier commands declared by the project.

  1. git clone https://github.com/11111000000/math-coding && cd math-coding && ./install.sh
    Installs the binaries, user-scope skill and complete methodology. It refuses to overwrite a foreign file; --force keeps backups.
  2. mathc init && mathc goal "GOAL" "src/,test/" "OWNER"
    The human states the goal and the owner. The tool never invents either.
  3. mathc add ID "REQUIREMENT" SCOPE "FALSIFIER" fact --requirement "verifier:COMMAND" --control "BREAKS_THE_SUBJECT"
    The claim receives a subject, a verifier and a control of its sensitivity.
  4. mathc run executes the verifier on the candidate and the control in an isolated copy. Then mathc map computes the states, and mathc next names the next action.
$ mathc map verdict: green core-laws holds strict-codecs holds cli-evidence holds … uncovered: 0 file(s)

The live map

This grid is not written by hand. It is generated at build time from spec.json and mathc map --json — the same output CI uses. If a claim’s evidence goes stale, this page says so after the next build.

What v5 refuses to do

  • Unknown is never shown as success; a waiver is never a pass.
  • Machine evidence never installs a judgment — only an external human review can.
  • A changed ADR makes its claims outdated, never silently green; history is never rewritten.
  • Reading verbs (map, next, context) never touch the working tree; controls run in isolated copies.
  • An agent cannot confirm its own claim by declaration alone.

Every claim on this page is checked by the tool the page describes. The methodology is the artifact; the artifact follows the methodology.
